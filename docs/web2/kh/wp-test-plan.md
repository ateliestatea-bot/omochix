# Knowledge Hub：実際の WordPress を使った隔離環境でのテスト計画（案）

- **使う環境**：使い捨ての WordPress だけ。本番・staging・他のセッションの Local サイトは使わない。
- **前提**：hooks の #75（ローダー）と、許可リストへの `glossary` の登録が入ったコードを使う。
- **このリポジトリのテストとの関係**：WordPress なしで動く `tests/glossary/run.php`・`theme.php` では、確かめられないことを確かめる。

## 0. 環境
- WordPress（最新版）、PHP 8.1 と 8.3 の両方、SQLite か使い捨ての DB。
- Slim SEO（本番と同じ版。版は T-PRE-3 で確認）。
- ユーザー：管理者・編集者・投稿者・寄稿者・購読者。未ログインでも確かめる。
- テスト用の用語：`content/glossary/terms/*.json` の5語（下書き）、それに不足・不正な用語。

実測していないこと：ブラウザーでのブロックエディター・Quick Edit・Bulk Edit の画面操作、実際の cron の起動、Web サーバー（FPM・Apache）での異常終了、メモリ不足による異常終了、XML-RPC の書き込み系のメソッド、ページキャッシュや CDN との組み合わせ、PHP 8.1／8.3 での WordPress の実行（PHP 8.1／8.3 は CI のテストで確認）。

確かめるだけで、直していないこと（P3。WordPress 本体の動作）：
- REST の `/wp/v2/comments?post={ID}` は、読めない投稿（下書き・非公開・予約・ゴミ箱・リビジョン）には 401、存在しない ID には空の一覧を返します。通常の投稿の下書きでも、本文・ヘッダーまで同じ応答です。
- コメント投稿（`wp-comments-post.php` に `comment_post_ID={ID}`）は、コメントが閉じている投稿には 403（「コメントは閉じられています」）、存在しない ID には空の 200 を返します。用語はコメントを受け付けないので、見えない用語は 403 です。コメントが開いている通常の投稿の下書きは 200 になるため、ここは用語集の設定で差が出ます（コメントが閉じた固定ページの下書きなどとは同じ応答）。変更前のコードは、コメントが開いた状態で保存された見えない用語のコメントを受け付けていました（302）。
  - 存在しない ID と同じ応答にするには、`comment_post_ID` を書き換える必要があります。Core の安全規則（T-SAFE：`$_POST` を読まない・書かない）に反するため、直していません。
- 2つとも、ID に何かがあることは分かりますが、用語集かどうか、slug・タイトル・本文は分かりません（応答の本文とヘッダーに出ないことを確認しました）。
- 最終 tree の再レビュー（Fable）で見つかり、直していない点：
  - P2（N2）：直しました（2026-11-26）。ログイン済みの非編集者に、見えない用語のタイトルと ID が出ていました。経路は、リンク挿入の検索（`wp-link-ajax`。見えない公開用語）、添付の「投稿を検索」（`find_posts`。下書き・予約・承認待ち・非公開の用語）、メディアの「アップロード先」（`read_post` が通るため、見えない公開用語）の3つです。`find_posts` は、`$_POST` を読まずに、`doing_action( 'wp_ajax_find_posts' )` の間の `pre_get_posts` で直しました（T-SAFE はそのまま）。実機の確認は下の「N2 の実機確認」を見てください。
  - P3：`/?author={ID}` が、用語しか持たない著者の URL へ転送します（WordPress 本体の canonical）。XML-RPC `mt.getTrackbackPings(ID)` で、ID の存在が分かります。
  - P3：同じプロセスの中だけで起きる変種です。承認済みの作成の中で、別の承認済みの作成が入れ子になる。例外を catch したあとに、続けて保存する（WP-CLI や常駐ワーカー）。ユーザーなしの保存で `tax_input` を信用する。公開中の通常投稿を用語に型変更する。公開中の用語に `publish_future_post` が届く。どれも、結果の用語は G-B で見えないままです。
- `/index.php/glossary/{slug}/` は `/glossary/{slug}/` へ 301 で転送します。要求した slug をそのまま Location に入れるだけで、存在しない slug でも同じです（転送先は、どちらも同じ 404）。

## N2 の実機確認（2026-11-26、WordPress 7.1.4、公開スイッチ ON は隔離環境だけ）
- 用語の状態は7通り：公開（見える）、公開（内容に不備）、公開（パスワード付き）、下書き、予約、非公開、承認待ち。比べた投稿タイプは、投稿・固定ページ・ai_tool・prompt・learn_practice（公開と下書き）です。
- 役割は6通り：管理者・編集者・投稿者・寄稿者・購読者・未ログイン。nonce は、サーバーが発行したものを使いました（購読者が画面で nonce を得られない場合も含めて、最悪の場合を試すため）。
- 修正前：投稿者・寄稿者・購読者には、`wp-link-ajax` で見えない公開用語2件のタイトルと ID が出ました。`find_posts` では、見えない用語6件が出ました。投稿者には、メディア一覧と `query-attachments` で、見えない公開用語2件のタイトルが「アップロード先」として出ました。
- 修正後：非編集者に出る用語は、見える公開用語だけです（`find_posts` には用語は出ません）。管理者と編集者の結果、ほかの投稿タイプの結果、未ログインの応答（400）は、修正前と同じです。
- ページ送り：見えない公開用語25件と見える用語3件を同じ語で検索すると、非編集者には見える3件が最初のページに出ます（見えない用語は、ページ送りの先にも出ません）。
- 公開スイッチ OFF：非編集者には用語が出ず、「アップロード先」のタイトルも出ません。
