# Learn 実践教材 運用手順（登録・編集・公開管理）

更新日：2026年10月25日
対象：Core Plugin 1.9.0 以降（Theme 1.25.0 以降）。管理画面の「Learn 実践教材」と、その配下の「JSON インポート」「JSON エクスポート」（どちらも管理者のみ）。
仕様の詳細は `docs/Learn-Phase4-Spec.md` §4〜§8。本書は運営者向けの手順だけを書く。

## 0. 原則

- 教材は **slug** で識別する。slug を後から変えない（JSON インポートが別の教材として新規作成してしまう）。
- 秘密情報（API キー・トークン・Webhook URL・秘密鍵・JWT）は書かない。必要な箇所はプレースホルダー `＜ここに貼る：LINE チャネルアクセストークン＞` の形で書く。それらしき値が含まれると保存も公開もできない。
- 公開は「必須 9 項目」が揃ってから：説明（summary）、所要時間、完成イメージ、プロンプト、手順、検証、安全性、最終検証日、参照した公式仕様。
- 編集を始める前にエクスポートで現状を保管する。まとまった編集は JSON（エクスポート → 編集 → dry-run → 反映）で行い、小さな直しは管理画面で行う。

## 1. 新しい教材を作る

### 1-A. 管理画面で作る
1. Learn 実践教材 → 新規追加。タイトルと本文（概要に出る短い導入）を入れる。
2. パネル 1〜8 を埋める。JSON のパネル（プロンプト・コード・手順・検証・よくあるエラー・出典・更新履歴）は「整形」「検証」ボタンで文法を確かめる。読めない JSON のまま保存すると、そのパネルは前回の値のまま保持され、通知が出る。
3. 分野（必ず 1 つ以上）・形式・対応AI・技術を右側のパネルで付ける。用途は必要なときだけ。
4. **下書き保存**してから **公開**する（必須が足りないと「公開できません。必須項目が未入力です：…」と出て下書きのまま。ブロックエディタでは、入力した項目を下書き保存してからもう一度「公開」を押す）。

### 1-B. JSON で作る
1. 既存の教材を 1 件エクスポートし（§3）、ファイルをひな形にする。`slug` を新しいものにし、`status` は `draft` のままにする。
2. JSON インポートで dry-run → 「新規作成 1」「エラー 0」を確認 → 同じファイルで反映。
3. 管理画面で内容を確認し、公開する。

JSON の形は `{"version": 1, "items": [ { "slug", "title", "status", "excerpt", "content", "menu_order", "meta": {…}, "terms": {…}, "relations": {…} } ]}`。`relations` は slug（Learn ページは `learn/tools/vercel` のようなパス、Motion は見本の slug）。存在しないタームはエラー、存在しない関連先は注意（無視）。

## 2. 既存の教材を直す

- 一部の文言や数値：管理画面で直して「更新」。公開中の教材は、必須が欠けても自動で下書きには戻らない（警告が出る。一覧の「必須」列も赤くなる）。
- 複数の教材をまとめて、または手順やコードを大きく：§3 のエクスポート → 編集 → dry-run → 反映。JSON にあるキーだけが更新され、無いキーは触らない。`""` / `[]` を書くとその項目は空になる。`null` は据え置き。
- 公開状態は JSON の `status` が明示された時だけ変わる。dry-run の「公開されます」「公開が取り下げられます」の注意を必ず読む。エクスポートしたファイルは現在の状態を持っているので、そのまま編集して取り込めば状態は変わらない。

## 3. エクスポート（保管・外部編集の元）

1. Learn 実践教材 → JSON エクスポート。「すべて」「公開中」「下書き」、または一覧でチェックした教材（一括操作「JSON エクスポート」）を選び、「JSON をダウンロード」。
2. ファイル名は `omochix-practice-<範囲>-<日時>.json`。編集前の保管用は日付付きで残す（Git 管理してもよい）。
3. 書き出した直後のファイルを dry-run すると全件「変更なし」になる。差分が出る場合は、保存済みの値が契約外だった（正規化された）か、関連先が削除されている。

## 4. 元に戻す（復元）

### 4-A. 管理画面の保存を戻す
投稿編集画面の「リビジョン」から版を選び「この版に戻す」。本文だけでなくメタ（プロンプト・手順・関連など）も戻る。クイック編集・JSON インポートの更新も版として残っている。

### 4-B. インポートを戻す
反映画面の「バックアップ JSON をダウンロード」を保存しておき、JSON インポートにそのまま読み込む。dry-run に「バックアップ JSON を読み込みました」と出て、各教材がバックアップ時点の内容に戻る更新として表示される。反映で戻る（バックアップ時に空だった項目は空に戻る）。

### 4-C. 保管しておいたエクスポートに戻す
§3 のファイルをそのまま dry-run → 反映。エクスポートは空の項目を省略しているので、後から足した項目は消えない（完全に戻すなら 4-B のバックアップを使う）。

## 5. 一覧での点検（定期）

- 「要再検証・未検証のみ」で絞り、最終検証日が 90 日より古い教材を再検証する。再検証したら日付を更新（クイック編集で可）。
- 「必須欠落のみ」で絞り、公開中で赤いものを優先して埋める。
- 「分野」「形式」「難易度」で偏りを見る。分野が無い教材はハブに出ない。

## 6. ターム（分野・形式・用途・対応AI・技術）

- 分野 8・形式 5・対応AI 10・技術 14 は初期登録済み。足す場合は先に「タクソノミー」画面で作る（JSON インポートは存在しないタームを作らない）。
- 分野は削除しない。削除すると教材から外れ、ハブに出なくなる。
- 用途は任意。付けると一覧の「用途」絞り込みが出る。

## 7. 100 件を超えるとき

- JSON は 1 ファイル 200 件・5 MB まで。分野ごとに分ける。
- ファイルをまたぐ教材同士の関連（`relations.practice`）は、相手がまだ無いと注意になり無視される。全ファイルを 1 回ずつ反映してから、もう一度同じ順で反映すると結ばれる（2 回目は関連だけが「更新」になる）。
- 画面が重いと感じたら、一覧の表示件数（表示オプション）を 20〜50 にする。

## 8. 本番での注意

- 本番 DB・FTP は運営者が操作する。エージェントは本番に書き込まない。
- 公開前に：必須が揃っている／プレースホルダーが残っていない（残して良いのは `＜ここに貼る：…＞` の形だけ）／関連先が存在する／最終検証日が今日に近い。
- 障害時：Core Plugin を 1.8.0 の配布物に戻しても教材データは残る（`release/` の deploy.md 参照）。
