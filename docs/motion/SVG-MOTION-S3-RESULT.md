## 1. 実装した内容

| 範囲 | 内容 |
|---|---|
| 書き出し形式 | 動く SVG、静止画 SVG、CSS、JS、設定 JSON |
| 使い方 | 画像として使う（推奨）、HTML に直接書く、HTML と CSS ファイル、JavaScript で操作する |
| 範囲の限定 | すべての規則を `omx-` とハッシュのクラス 1 つに限定。ロゴ自身の `<style>` も同じ範囲に閉じる |
| ID | ロゴの ID に範囲の接頭辞を付け直す。安全でない ID（`SAFE_ID` に合わない）は取り除く |
| 動きを減らす設定 | 画像は `<picture>` で静止画に切り替え。他の形式は CSS で停止し、終了時の姿勢で止める |
| 検査 | 書き出す前に全出力を検査（`verifyExport`、`cssIsClean`）。通らなければ出力しない |
| 画面 | 使い方の選択、ロゴの説明（alt）、コードの表示とコピー、ダウンロード、設定 JSON の保存と読み込み |
| 設定 JSON | 形式名とスキーマ番号を確認し、ロゴは最初から安全処理をやり直す。理由ごとに日本語で表示 |

コードは `textContent` で表示し、ファイル名は固定（`omochix-logo-motion-<プリセット>.svg` など）で入力由来の名前を使わない。

## 3. WordPress での確認

Local の停止中サイトを複製した検証用環境（WordPress 7.1.4）で確認した。元サイトのデータは確認前後でハッシュが一致（変更なし）。複製は確認後に停止し、置いたファイルは削除した。

| 確認 | 結果 |
|---|---|
| 書き出した 2 つの SVG を uploads に置き、`<picture>` を「カスタム HTML」ブロックとして表示 | 3 エンジンで表示され、動く。エラー 0 |
| 動きを減らす設定 | 3 エンジンで静止画に切り替わり、動かない |
| 配信の種類 | `image/svg+xml` |
| 管理者と編集者（`unfiltered_html` あり）の保存 | `<picture>` がそのまま残る |
| それ以外（投稿者など）の保存（`wp_kses_post`） | `<picture>` と `<source>` が消え、`<img>` だけが残る。動きは出るが、静止画への切り替えは効かない |
| SVG のアップロード | WordPress 標準では不可（S3 設計時に確認） |

手順は `docs/motion/SVG-MOTION-EMBED-GUIDE.md` にまとめた。
