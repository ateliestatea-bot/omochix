### 発見して修正した干渉

`page-learn-article.php` の関連記事と NEXT は、同じ親の固定ページを `WP_Query` で取得する。Learn の子ページとして作ると、**既存 3 ページで関連記事が押し出された**（例：`/learn/basics/` の「Tools」が消える）。順序の指定だけでは、`/learn/tools/` に NEXT が増えた。

既存ファイルを変えず、`inc/learn-svg-motion.php` の `pre_get_posts` で、このクエリだけから除外した。修正後は**公開 20 ページの HTML が作成前と完全一致**し、サイトマップ掲載と直接アクセスは維持された。

最初の修正（`get_pages` のフィルター）は実際の経路に効かず、比較で判明して作り直した。

### 未確認

実際の nginx と Local の構成ではなく PHP 内蔵サーバーで動かした。本番のロリポップ！アクセラレータ、キャッシュ系は未確認。

## 2. 3D と filter の事前計測

### 描画されるか（中間状態と基準の画素差、%）

| 効果 | Chromium | Firefox | WebKit |
|---|---|---|---|
| blur を `<g>` に | 11.78 | 11.78 | **0** |
| blur を `<svg>` に | 6.46 | 6.48 | 6.70 |
| drop-shadow を `<g>` に | 9.12 | 9.47 | **0** |
| drop-shadow を `<svg>` に | 4.50 | 4.52 | 3.68 |
| rotateY を `<g>` に | 6.79 | 7.63 | 3.58（弱い） |
| rotateY を `<svg>` に | 7.98 | 8.13 | 11.96 |

**WebKit は SVG の内側要素の CSS filter を描画しない。** 計算値は正しく見えるので、画素比較でしか分からない。

### 負荷（Chromium、CPU 20 倍、FPS）

| 要素数 | blur `<g>` | blur `<svg>` | shadow `<g>` | shadow `<svg>` | rotateY `<svg>` |
|---|---|---|---|---|---|
| 200 | 60 | 60 | 60 | 60 | 60 |
| 1,000 | 14 | 60 | 14 | 60 | 60 |

Firefox（Playwright 版、GPU なしのヘッドレス）は 1200×675 で rotateY 26〜35fps、filter 44fps まで低下する条件があった。640×360 では 100fps 超。本番の枠は PC で幅 400px 以下、タブレットでも高さ 260px 以下で、大きな枠の負荷は実機未確認。

**判断：Go。** filter と 3D は `<svg>` 要素に当てる。

## 5. Safari の約 22fps

### 計測結果

| 条件 | WebKit 27.2 | Safari 26.6.2 実機 |
|---|---|---|
| 上位ページ / 同一オリジン枠 | 60 / 60 | 60 / 60 |
| sandbox 枠（操作前） | 22 | 22〜23 |
| `allow-pointer-lock` 追加、`allow` 属性、blob URL、大きな枠 | 22〜23 | 22〜23 |
| 親のクリック、`focus()`、ホバー | 23 | `focus()` 23、他は未測定 |
| **枠内クリック** | **60** | **未測定** |
| キーボードで枠内へ移動 | 60 | 未測定 |
| **枠を作り直す** | **22 に戻る** | 未測定 |
| **`<img>` の描画（1 秒あたりの異なる描画数）** | **60.5** | **61** |

### 描画負荷との関係

負荷とは無関係。WebKit で 2,000 要素でも、クリック前は 23fps、クリック後は 60fps（transform、blur、rotateY、drop-shadow すべて）。**ブラウザが操作前の別オリジン枠に課す上限**であり、軽量化では解決しない。

### 実用上の体感差

**未評価。** 私は映像を目視できない。数値としては、1 コマ約 45ms、700ms の登場で約 15 コマ（60fps なら約 42 コマ）。`tests/svg-motion/pages/safari-compare.html` で同じ動きを見比べられる。

### 安全性を維持した改善方法

| 方法 | 効果 | 状態 |
|---|---|---|
| プレビューのクリックで再生・停止 | クリック後は 60fps | 実装済み |
| 一覧を `<img>` にする | 低下なし（実機 61） | 実装済み |
| 枠を作り直さず、枠内で SVG を差し替える | ロゴや P12 への切替で 22 に戻らない | **未実装（推奨）** |
| 操作前のプレビューを `<img>` にする | 実機で低下なし。スクリプト不要で、より安全 | **未実装（S2 で検討）**。任意時刻への移動ができない |
| `allow-same-origin` や同一オリジン枠 | 60fps になるが**隔離が破れる** | **不採用** |

### 実機 Safari のクリック前後

自動クリックは macOS のアクセシビリティ権限で拒否された。設定は変更していない。**未測定。** 次の手順で約 30 秒で測れる。

**結論：未解決。公開ブロッカーとして記録する。** 回避策は実機未確認で、操作前の約 22fps も残る。

## 6. P20（形状変化）の残課題

本実装に含めていない。SMIL 限定の実験機能として別管理する。

1. CSS `d` は Safari 非対応のため、WAAPI と CSS では作らない。SMIL は S1-A で 4 環境とも動作確認済み。
2. 入力の SMIL は安全処理で除去するので、**生成した SMIL だけを入れる経路**と検証器の例外が必要。そのまま緩めない。
3. 節点数の異なるパスの対応付け方法が未設計。
4. seek は `setCurrentTime` になり、WAAPI のタイムラインと別管理になる。
5. reduced-motion は `@media` で止められず、書き出し時の扱いが必要。
6. CSS 書き出しは不可で、`<img>` での SMIL 再生は S1-A で確認したのみ。
7. 枠内の更新低下の影響は未測定。
