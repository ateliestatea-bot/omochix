# SVG Motion Studio S2 実装結果

検証日：2026年11月3日
ブランチ：`feature/svg-motion-s1b`。S1-C は `213e7d3`、S2 は同じブランチの次のコミット。
本番 WordPress、本番 DB、FTP、Core、AI Tools、既存 53 教材、Theme 1.27.0 の配布物は変更していない。push、PR、merge、deploy なし。

## 1. 実装した内容

| 範囲 | 内容 |
|---|---|
| 入力 | ファイル選択、ドラッグ＆ドロップ、コード貼り付け。MIME、拡張子、容量、UTF-8、内容、複雑度を検証 |
| 拒否 | 16 種の理由を日本語で表示。失敗しても現在のロゴを維持 |
| 解析 | 図形、文字、画像を判定。使えないプリセットは無効にして理由を表示。1 パーツは全体で動かす |
| プレビュー | B+（`<img>`）。iframe の再生成を廃止。再生、停止、再開、リセット、切替、スライダー |
| 調整 | 遅れ、動き方、繰り返し、時間差、不透明度、大きさ、横と縦の位置、回転、長さ、プリセット固有値 |
| 保存 | IndexedDB に正規化済み SVG と設定。読み込み時に再正規化。旧形式の移行、不明形式の削除、利用者による削除 |

共通の位置と大きさは専用のラッパーに当てるので、プリセットの動きと競合しない。再生状態は保存しない。

### B+ で実現できないこと

19 プリセットはすべて B+ で動作した。次は B+ の制限で、S2 の範囲には影響しない。

| 制限 | 代替 |
|---|---|
| 画面上で図形をクリックして選べない | 必要になった段階で sandbox 枠（案 A）を使う。`buildDocument` は残している |
| 変更のたびに画像を作り直す | 上限内では問題なし（第 4 章）。2,000 パーツで約 10ms |
| 位置や拡大でロゴの枠を出た部分は切れる | 仕様。全消去にはならないことを確認（第 6 章） |
| 将来サイトに CSP を入れる場合 | `img-src blob:` の許可が必要 |

## 2. 検証環境

Chromium 156、Firefox 157、WebKit 27.2（いずれも Playwright 版）、Safari 26.6.2（実機）。

**実機 Safari で実行したのは、B+ のプレビュー部品の自走計測のみ。** アップロード画面の操作は自動化できず、実行していない。

## 3. セキュリティ QA

攻撃は**実ページのアップロード経路**（ファイル選択と貼り付けの両方）から通した。3 エンジン共通の結果。

| 項目 | ファイル | 貼り付け |
|---|---|---|
| 攻撃 69 種：受理 / 拒否 | 63 / 6 | 63 / 6 |
| 実行 | 0 | 0 |
| 外部通信（検知サーバーへの着信） | 0 | 0 |
| 目印の描画（**黒い図形と重ならない位置に移動して画素で確認**） | **63 / 63** | **63 / 63** |
| 親ページ DOM への SVG 挿入、iframe、URL へのロゴ | 0 | 0 |

- **拒否の 6 種：** `scriptNs`（NOT_SVG）、`xxe`、`dtdExt`（DOCTYPE）、`onload`、`onUpper`、`xmlStylesheet`（描画内容なし）。拒否後も直前のロゴが残ることを画素で確認した。
- **検知器の陽性対照：** 実行、外部通信、送信、目印の各検知器が実際の事象に反応し、目印がないロゴでは反応しないことを確認した。合わせて、未処理 SVG を sandbox のみに入れる対照で、実行 9〜14 種、通信 17〜28 種を検出した。
- **空の結果を合格にしない：** 取り込み時に描画内容を確認し、描画がないものは `EMPTY_RESULT` で拒否する。
- **資源攻撃 11 種：** すべて期待どおり（`useCycle` は描画なしで拒否）。最悪 166ms で固まらない。
- **正常 SVG 17 種：** アップロード経路の表示で描画差 0%。内部参照（グラデーション、マスク、`use` など）を維持。
- **保存データへの直接注入：** 実行 0、親ページへの挿入 0。
- **悪意あるファイル名：** 文字として表示され、マークアップにならない。

## 4. B+ の誤差と性能

### 位相誤差（ms、中央値 / 最悪）

一定速度の動きの重心から画像の実際の時刻を求め、プレビューの内部時刻と比較した。**計測の分解能は 12.5ms（1px）で、これ未満は区別できない。**

| 場面 | Chromium | Firefox | WebKit | Safari 実機 |
|---|---|---|---|---|
| 再生中 | 13 / 31 | 3 / 32 | 26 / 30 | 27 / 31 |
| パラメータ変更後 | 12 / 27 | 14 / 20 | 13 / 30 | 13 / 28 |
| 停止後 | 13 / 13 | 13 / 13 | 13 / 13 | 13 / 13 |
| 再開後 | 18 / 44 | 26 / 31 | 4 / 22 | 3 / 6 |
| 指定時刻で凍結 | 13 / 13 | 13 / 13 | 13 / 13 | 13 / 13 |

最悪 44ms。60fps の約 3 コマ分。凍結した画像と WAAPI の基準は、19 プリセット × 3 ロゴで画素差 0%、CSS と WAAPI の計算値の差も 0。

### スライダーのドラッグ（Safari 実機、更新 1 回あたり）

| ロゴ | 回/秒 | 中央値 | 最悪 |
|---|---|---|---|
| 見本相当 | 60.5 | 5ms | 7ms |
| 200 パーツ | 61 | 5ms | 9ms |
| 2,000 パーツ | 61 | 10ms | 13ms |

### Safari の描画頻度

| 方式 | 実機 Safari |
|---|---|
| 以前の sandbox 枠（操作前） | 22 回/秒 |
| B+（描画回数 / 異なる描画数） | 60.5 / 55 回/秒 |

異なる描画数は canvas に描いて数えた代用値で、**実際の画面の滑らかさの目視ではない。**

## 5. 検証で見つけて直した実バグ

| 問題 | 影響 | 検出 |
|---|---|---|
| WebKit の `replaceState` 制限（10 秒に 100 回）で例外 | **Safari で正常なロゴが拒否される** | WebKit のみ |
| 右パネルでプレビューが再生ボタンと題名を覆う | 操作不能 | 実画面テスト |
| 静止中に長さを変えると途中の状態で止まる | **reduced-motion でロゴが半透明に** | 調整テスト |
| 登場系のリセットでロゴが消える | ロゴの消失 | 上記の修正時 |
| 保存ロゴの ID 接頭辞が再読み込みで増える | データの肥大 | 実装時 |
| `var()` の参照先を除去しても参照が残る | ロゴの色が壊れる | 目印の画素確認 |

追加した回帰テスト：操作要素が他の要素に覆われていないことの確認（`elementFromPoint`）。
