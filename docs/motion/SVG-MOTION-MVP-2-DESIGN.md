## 1. WordPress ショートコード

### 1-1. 解決したいこと

- [事実] `<picture>` を「カスタム HTML」で貼ると、`unfiltered_html` のないユーザー（投稿者、寄稿者）の保存で `wp_kses_post` が `<picture>` と `<source>` を消す。`<img>` だけが残り、「動きを減らす」設定で静止画に切り替わらなくなる（S3 結果、WordPress 7.1.4 の複製で確認）。
- [事実] WordPress は標準で SVG のアップロードを受け付けない。
- [推奨] SVG のアップロードを許可する設定やプラグインは使わない。サイト全体の攻撃面になるため。

### 1-2. 推奨方式：テーマのショートコード（後で同じ描画関数をブロックに載せる）

```
[omochix_logo_motion name="omochix-logo-motion-pop" alt="OmochiX のロゴ" size="200"]
```

| 項目 | 設計 |
|---|---|
| 置き場所 | テーマ内（Core は変更しない）。`inc/logo-motion-shortcode.php` |
| ファイルの場所 | 管理者がサーバーの固定フォルダーに置いたファイルだけ。`wp-content/uploads/omochix-logo-motion/` |
| `name` | `^[a-z0-9-]{1,64}$` のみ。`{name}.svg` と `{name}-static.svg` の両方があるときだけ表示。`realpath()` が固定フォルダーの中にあることを確認（`..`、シンボリックリンクで外へ出られない） |
| `alt` | 必須。`esc_attr()`。空なら装飾扱い（`alt=""`、`aria-hidden` は付けない） |
| `size` | 整数で 16〜1024 に丸める。それ以外の値や単位は既定の 200 |
| 出力 | PHP が組み立てる `<picture><source media="(prefers-reduced-motion: reduce)" srcset="…-static.svg"><img src="….svg" alt="…" width height loading="lazy" decoding="async"></picture>`。URL は `esc_url()` |
| 使えない値 | 任意の URL、外部ホスト、`style`、`class`、イベント属性。属性は 3 つ以外を無視する |
| 見つからないとき | 何も出さない。ログイン中で `edit_posts` を持つユーザーにだけ HTML コメントで理由を出す（公開側には出さない） |
| 読み込み | スタジオの JS / CSS は読み込まない（画像を表示するだけ） |
| キャッシュ | ファイルの更新時刻を `?v=` に付けてキャッシュを切り替える |

**kses を避けられる理由 [事実＋推奨]**：投稿本文に保存されるのはショートコードの文字列だけで、kses は `<picture>` を見ない。HTML は表示時に PHP が作るので、権限に関係なく同じ安全な出力になる。

**SVG の中身は信頼しない [推奨]**：スタジオの書き出しは安全処理を通しているが、固定フォルダーに別のファイルが置かれる可能性はある。`<img>` と `<picture>` で表示する限り、SVG 内のスクリプトや外部参照はブラウザーが実行・取得しない（S1-A〜S3 で確認済みの性質）。`<object>`、`<embed>`、`<iframe>`、インライン展開はショートコードでは使わない。

### 1-3. ブロック（MVP-2 の後）

同じ描画関数 `omochix_logo_motion_render( array $atts ): string` を、`register_block_type` の `render_callback` からも呼ぶ。エディターでの選択 UI はファイル名の一覧（固定フォルダーの中身）に限る。

### 1-4. テスト [推奨]

- PHP の契約テスト：名前の拒否（`../x`、`a/b`、大文字、65 文字、空）、片方のファイルだけある場合、`realpath` で外を指すシンボリックリンク、`alt` のエスケープ、`size` の丸め、出力に `<script`、`on*=`、`style=` がないこと。
- 複製した WordPress（本番ではない）で、投稿者・寄稿者・編集者・管理者の 4 権限で保存し、表示 HTML が同じであること。動きを減らす設定で静止画に切り替わること（3 エンジン）。

## 2. 投稿権限別の安全な埋め込み

| 権限 | `unfiltered_html` | カスタム HTML の `<picture>` | ショートコード | 推奨 |
|---|---|---|---|---|
| 管理者（単一サイト） | あり | 残る | 使える | ショートコード |
| 編集者（単一サイト） | あり | 残る | 使える | ショートコード |
| 投稿者 | なし | `<picture>` が消える | 使える | ショートコード |
| 寄稿者 | なし | `<picture>` が消える | 使える（公開は編集者の承認後） | ショートコード |
| マルチサイトの管理者 | なし（特権管理者のみあり） | 消える | 使える | ショートコード |

- [推奨] 権限に関係なくショートコードを案内の第一にする。カスタム HTML の手順は、`unfiltered_html` を持つ人向けの「ショートコードが使えない場合」に下げる。
- [推奨] `unfiltered_html` を他の権限に追加する案は採らない（サイト全体で任意の HTML とスクリプトを許すことになる）。
- [推奨] インライン SVG、外部 CSS、JS の書き出しは「テーマやサイトの開発者向け」とし、投稿本文での使用は案内しない。
- [未検証] マルチサイト環境での確認は行っていない。

## 3. 実機テスト手順

### 3-1. 対象

| 端末 | ブラウザー | 必須 |
|---|---|---|
| iPhone（iOS 最新と 1 つ前） | Safari | 必須 |
| iPad（iPadOS 最新） | Safari | 推奨 |
| Android（最新と 1 つ前） | Chrome | 必須 |
| Mac（macOS 最新） | Safari、Chrome、Firefox | 必須 |
| Windows 11 | Chrome、Edge、Firefox | 必須 |

### 3-2. 手順（各端末で）

1. スタジオを開く。19 プリセットを順に選び、プレビューが動くことを目視（1 プリセット 5 秒）。
2. 見本ロゴ 3 種と、自分のロゴ 1 つ（ファイル選択、貼り付け）で同じことをする。
3. 書き出し：4 つの使い方でコピー、SVG・静止画・CSS・JS・JSON をダウンロード。iOS では「ファイル」に保存されることを確認する。
4. 書き出したファイルをテスト用ページ（`<picture>`、`<img>`、背景、インライン）で開き、動いて最後に止まることを確認する。
5. OS の「動きを減らす」をオンにする（iOS：設定 > アクセシビリティ > 動作、Android：ユーザー補助 > アニメーションを削除、macOS：アクセシビリティ > ディスプレイ）。スタジオのプレビューと書き出しが静止画になることを確認する。確認後に元へ戻す。
6. Safari の約 22fps（S1-C）：`tests/svg-motion/pages/safari-click.html` で、クリック前後の値を記録する。
7. スクリーンリーダー（VoiceOver、TalkBack、NVDA）で、状態文（読み込み、取り消し、原点のフォールバック、コピー）が読まれることを確認する。

### 3-3. 記録と判定

- 記録：端末、OS、ブラウザーの版、手順番号、結果（OK / NG / 未実施）、画面録画またはスクリーンショット。
- 判定：必須の端末で NG 0。NG は内容と再現手順を記録し、修正するか既知の制限として公開前チェックリストに残す。**未実施を OK にしない。**

## 4. 実 SVG 互換性テスト

### 4-1. 集める SVG

自分で作った、または利用許諾のある SVG だけを使う。第三者のロゴは使わない。

| 作成ツール | 特徴 |
|---|---|
| Figma | `<defs>` の多用、`clipPath`、`mask`、`filter`、ID の連番 |
| Illustrator（SVG 1.1、スタイル：内部 CSS／プレゼンテーション属性の両方） | `<style>` のクラス、`enable-background`、`xml:space` |
| Inkscape | `sodipodi:` と `inkscape:` の名前空間、`<metadata>` |
| Affinity Designer | 入れ子の `<g>` と変換行列 |
| Canva | 埋め込み画像（PNG の data URI）、フォントのアウトライン化の有無 |
| Sketch | `<use>` と `<symbol>` |

各ツールについて：単色ロゴ、グラデーション、テキストを含む（アウトライン化あり／なし）、マスク付き、パーツ 200 超、の 5 種。

### 4-2. 判定

| 項目 | 合格条件 |
|---|---|
| 受け付け | 受け付けるか、理由つきで拒否する（落ちない、固まらない） |
| 描画 | 元の SVG と並べた画素差（既存の fidelity テストと同じ基準） |
| 失われるもの | 除去された要素・属性の一覧を記録し、見た目に影響するものは既知の制限に載せる |
| 書き出し | 19 プリセットで書き出せる。CSS 上限（256KB）を超える場合は理由が表示される |

自動化：`tests/svg-motion/fixtures/real/` に置き、既存の fidelity と同じ手順で 3 エンジン比較する（CI では fast に含める）。

## 5. セキュリティ最終レビュー

| 範囲 | 確認すること |
|---|---|
| `safety.js`（DOMPurify と独立した検証器） | 許可リストの差分、名前空間、CSS の再構築、`var()` 禁止、ID の付け替え、`<use>` の展開 |
| sandbox 枠（`frame.js`） | `allow-scripts` のみ、nonce CSP、`postMessage` の送信元と形の検査、計測枠（MVP-1 で追加した経路を含む） |
| 書き出し（`export.js`） | SVG、CSS、JS、JSON に利用者の文字列が入る箇所のエスケープ（代替テキスト、ファイル名は固定） |
| 設定 JSON と IndexedDB | 大きさの上限、schema 1 / 2 の検査、未知のキーの拒否、壊れた記録の削除 |
| ショートコード（MVP-2） | 1-2 の名前・パス・属性の検査 |
| 依存 | DOMPurify 3.4.17 の既知の脆弱性の確認、更新手順 |

- **ファジング [推奨]**：攻撃コーパス（69 種）を元に、要素・属性・CSS を組み替えた SVG を 1 エンジンあたり 1 万件生成し、安全処理 → 検証器 → 書き出し → 表示を通す。実行 0、外部通信 0、検証器の見逃し 0 を条件にする（夜間ジョブ、PR では回さない）。
- **第三者レビュー [推奨]**：上の表を範囲として、外部またはこのリポジトリに関わっていないレビュアーに依頼する。指摘は重大度ごとに記録し、高以上は公開前に修正する。
