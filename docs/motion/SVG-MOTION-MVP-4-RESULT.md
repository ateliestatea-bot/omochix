## 3. SVG の直接アクセス：配信の設計（本番には未適用）

| ヘッダー | 値 | 理由 |
|---|---|---|
| `Content-Type` | `image/svg+xml` | 画像として扱われる。`text/html` などで返さない |
| `X-Content-Type-Options` | `nosniff` | 種類の推測をさせない |
| `Content-Security-Policy` | `default-src 'none'; style-src 'unsafe-inline'; img-src data:; sandbox` | 直接開いたとき、スクリプト・フォーム・外部読み込みを止める（一意のオリジン）。書き出しのインライン CSS と data URI の画像は表示される |

- **`<picture>` / `<img>` 経由**：画像として読み込まれた文書には、応答の CSP は効かない。表示、動き、reduced-motion の切り替えは変わらない（3 エンジンで確認）。
- **SVG 単体を直接開いた場合**：書き出しのファイルは CSS アニメーションなので、`sandbox` の下でも表示されて動く。スクリプトは動かない。
- **設定例**：Apache / LiteSpeed の `.htaccess` と nginx の `location` を、`SVG-MOTION-EMBED-GUIDE.md` の 3 章に載せた。
- **CDN とキャッシュ**：`?v=` が中身の hash なので、クエリ文字列を区別するキャッシュでは差し替えがそのまま反映される。クエリを無視する CDN の場合、`?v=` は使えないので、差し替えのたびに削除が必要。CDN が応答ヘッダー（特に CSP と `nosniff`）を消さないことを確かめる。
- [未検証] 本番（ロリポップ！とアクセラレータ）で `.htaccess` の `Header` が効くか、ヘッダーがそのまま返るか。公開前に `curl -I` で確かめる。
