## B+. 索引の古いキャッシュが残る時間（公開 → 非公開・保護への変更）

目的：正常な 200 の索引がキャッシュされた後に、記事を非公開・パスワード保護・下書き・ゴミ箱へ変えたとき、その**題名と URL** が各キャッシュ層にどれだけ残るかを測る。本文は漏れない（保護ページはパスワード入力、非公開・下書きは 404 になる）。

### 区別する 2 種類の情報

| 種類 | 内容 | キャッシュ対策で防げるか |
|---|---|---|
| (a) 公開中に取得済みの情報 | 公開していた間に誰かが取得した題名と URL（ブラウザ、開いたタブ、保存されたファイル、検索エンジンなど） | 防げない。公開していたこと自体による開示で、取り消せない |
| (b) 非公開化後に新たに取得できる情報 | 非公開にした**後**のリクエストに、キャッシュが古い索引を返したもの | 防げる。このセクションで測るのは (b) の時間 |

J5・J6・J9 で測るのは (b)。J8 の「開いたタブ」は (a)。開いたタブは新しく取得するわけではないので、(b) には数えない。

### 現行設計から想定される残存時間

以下は**現行設計から想定される残存時間**で、実測値ではない。**安全性の面で承認された許容値でもない**。許容値は、運営者が別途決める。

| 層 | 消える仕組み | 想定される残存時間 |
|---|---|---|
| L1 WordPress の transient | `save_post`・`trashed_post`・`deleted_post` などで即時に削除 | 0 秒。ただし、これらのフックを通らない変更（DB の直接編集、一部の一括処理や移行ツール）では、transient の有効期限まで最大 900 秒 |
| L2 ホストキャッシュ・LiteSpeed | `s-maxage=300` で期限切れ。投稿を更新したときに REST をパージするかは設定次第 | 300 秒以内 |
| L3 CDN（ある場合） | `s-maxage=300` | 300 秒以内。ただし合成すると下の C2 のとおり |
| L4 ブラウザの HTTP キャッシュ | `max-age=300` | 300 秒以内。ただし合成すると下の C1・C2 のとおり |
| L5 開いているタブのメモリ | 索引はページ内に保持され、期限はない。ページを移動・再読み込みすると L4 から取り直す | **期限なし（未解決の制約）**。これは (a) の情報を表示し続けるもので、(b) の取得ではない。それでも、非公開にした題名が候補として出続けるので、制約として残す |

### 層を重ねたときに想定時間を超える場合（検証すること）

想定時間は、各層が「生成からの経過時間（`Age`）」を引き継ぐことを前提にしている。前提が崩れると、層を重ねた分だけ残存時間が延びる。

| # | 合成 | 前提が崩れたときの最大値（理論値） | 確認する方法 |
|---|---|---|---|
| C1 | L2 + L4 | L2 が `Age` を付けないと 300 + 300 = 600 秒 | L2 の応答に `Age` があるか、ブラウザがそれを引いて期限を計算するか |
| C2 | L2 + L3 + L4 | 3 層とも `Age` を引き継がないと 900 秒 | CDN が origin の `Age` を引き継ぐか |
| C3 | stale 配信（`stale-while-revalidate`・`stale-if-error`） | 期限切れの後も、CDN や LiteSpeed の既定の設定で古い応答を返し続ける可能性がある（上限は設定次第） | 期限切れの直後に `Age` > 300 の応答が返らないか |
| C4 | L1 のフックを通らない変更 + L2〜L4 | 900 秒 + 上の値 | 運用で、非公開化を管理画面以外で行うかどうか |
| C5 | 304 による再検証 | ETag は付けているが、サーバーは条件付きリクエストにも 200 の全文を返す。古い応答を延命する経路ではないことを確認 | `If-None-Match` 付きのリクエストの応答 |

### 対策の候補（今回は実装しない）

| 候補 | 効果 | 影響・コスト |
|---|---|---|
| T1 `s-maxage`・`max-age` を短くする（例：60 秒） | L2〜L4 の (b) の時間が短くなる | origin へのリクエストが増える（索引は transient から返すので 1 回あたりは軽い）。L5 には効かない |
