## 1. 目的と範囲

Web デザイン・動画モーション・プロンプト・制作手順を、1 つの作品ライブラリとして扱う。

- 参考にしたサイト（prompt-motion.com）からは、「作品ごとにプレビュー・プロンプト・制作情報をまとめる」という**構成の考え方だけ**を取った。コード・作品・画像・文章・ブランド要素は複製していない（ページの中身も取得していない）。
- **実装しないもの**：Blender による本格 3D 制作、AI 動画生成、ライブ編集、動画レンダリング機能、会員・課金、有料 API、任意 HTML/JS のアップロード、新しい制作エンジン。データモデルの語彙（`technologies` の `canvas` / `remotion` / `blender`）と、Motion Studio への受け渡し形式（§5）だけを定義した。

## 2. 既存機能との重複と統合

| 既存機能 | 重なるところ | D1.5 での扱い |
|---|---|---|

### 2.1 Motion Studio の確認結果（読み取りのみ）

- 場所：OmochiX Motion Studio の別リポジトリ（ローカルのチェックアウト）。確認時のブランチは `batch-03-premium` で、未コミットの変更が 110 件あった（別の作業中のため触れていない）。
- テンプレートに当たるもの：`src/videos/registry.ts` に登録された動画 ID（Remotion のコンポジション ID。例：`rag-intro`）。
- 編集・読み込みの手段：ローカル開発用の Remotion Studio（`npm run dev`、`localhost:3000`）と、`npm run produce <videoId>` だけ。**公開された編集画面、テンプレートを読み込む API、パラメーターを受け取る入口は見つからなかった**。→ 制作ボタンの条件（実在し、動作を確認できること）を満たさない。
- 既存動画の再利用：見送った。VOICEVOX の規約確認は記録されているが、BGM は「仮 BGM」のままで、人の耳での確認も「未確認」と記録されている（`audits/2026-11-03-prepost/README.md`）。実在する製品名やニュースを扱う動画もある。**権利と仕上がりの確認が終わっていないため、公開作品として登録しない**。
- 連携の可否：**UNVERIFIED**（データ形式の設計のみ。実際の受け渡しは未試験）。

## 3. 作品データモデル（カタログ v2）

テーマ同梱の JSON（`assets/data/design/catalog.json`）を v1 から v2 に拡張した。**DB テーブルと投稿タイプは増やしていない**。スキーマは `catalog.schema.json`（draft 2020-12）、同じ規則を PHP の検証器（`omochix_design_validate_catalog()`）でも確認する。

### 3.1 分類の軸

| フィールド | 値 | 用途 |
|---|---|---|
| `medium` | `web` / `video` / `app` / `component` | 種類。**公開できるのは `web` と `video`**（`app`・`component` は D0 §16 のとおり保留。公開状態にすると検証で拒否） |
| `use_cases` | lp, corporate, product, saas, media, portfolio, brand-intro, sns-short, explainer, presentation | 用途（絞り込み） |
| `motion_types` | scroll, 3d, typography, logo, chart, pointer, transition, ambient, ui | 表現（絞り込み） |
| `technologies` | html, css, js, svg, webgl, canvas, ffmpeg, remotion, blender | 技術（絞り込み）。canvas・remotion・blender は語彙だけで、使う作品はまだない |
| `styles`・`motions`・`industries`・`level` | D1 のまま（`motions` に `logo-draw` を追加） | 見た目・細かい動きのタグ、業種、難易度 |

### 3.2 作品ごとに持てる情報

| 指示書の項目 | フィールド | 必須 |
|---|---|---|
| 安定した作品 ID | `id`（`dl-{medium}-NNNN`、一意。slug を変えても変わらない） | ○ |
| タイトル・概要 | `title`・`summary`・`description` | ○ |
| 静止画・動画プレビュー | `poster`（AVIF）・`posterFallback`（WebP）・`loop` / `loopFallback`（カード用）・`video`（動画作品の本編：mp4・webm・幅・高さ・fps・秒） | poster ○、video は動画作品で必須、それ以外では禁止 |
| 制作技術・必要素材 | `technologies`・`materials[]`（名前・種類・出典 `original` / `system`・ライセンス `original` / `system-font`） | ○ |
| カスタマイズ可能項目 | `customization[]`（ラベルと説明。**画面で値を変える機能はまだない**ことを明記して表示） | ○（空でも可） |
| プロンプトと制作手順 | `prompt.text`・`steps[]`（1〜10 件） | 任意 |
| 配布可能なコード・素材 | `deliverables`（Web のみ：デモのソースの SHA-256 と `showCode`）。表示するコードはデモの実ファイルから作る | Web で必須 |
| 作者・出典・ライセンス | `credits`（`source` と `license` は **`original` だけ受け付ける**。第三者の素材を含む作品は登録できない） | ○ |
| 動作確認環境・確認日・既知の制約・検証状態 | `verification`（`state`・`checked`・`environments[]`・`limitations[]`）。**`unverified` 以外の状態には確認日と環境が必須** | ○ |
| 関連 Learn 記事 | `related.learn`（Learn の固定ページのパス。公開中のものだけ表示）・`related.motion`（Gallery の見本）・`related.designs`・`related.prompts` | ○（空でも可） |
| 対応 Motion Studio テンプレート ID | `motionStudio`（§5） | 任意 |
| 性能の記録 | `audit.perf` | ○（空でも可） |

テキストは制御文字と `<` `>` を拒否する（プロンプトと手順は改行だけ許可）。正規表現は `\z` で終端を固定し、末尾の改行で検証をすり抜けられないようにした。`{}` と `[]` の取り違えも、オブジェクトとして読み直して確認する。

### 3.3 既存 4 作品の移行

D1 の 4 作品は、id・slug・メディア・デモ・ハッシュを変えずに v2 へ移した（変換スクリプトで機械的に変換し、用途・表現・技術・素材・手順・変えられるところ・検証情報を追記した）。`audit.isolation` は `verification.state` に移った。

## 5. Motion Studio との連携（設計のみ）

### 5.1 対応関係

```
Design Library 作品 ID（dl-video-0001）
  → Motion Studio テンプレート ID（Remotion のコンポジション ID、例：rag-intro）
  → 編集設定（settings：スカラー値だけの小さな辞書）
```

カタログの `motionStudio`：

```json
"motionStudio": {
  "templateId": "rag-intro",
  "status": "unverified",
  "settings": { "title": "…", "accent": "#a78bfa", "seconds": 6 }
}
```

- `templateId`：`^[a-z0-9](?:[a-z0-9-]{0,62}[a-z0-9])?$`（パス・URL は入らない）。
- `status`：`unverified` / `verified`。`verified` は、Motion Studio 側でそのテンプレートが実在し、`settings` を渡して書き出せることを確認した場合だけ使う。
- `settings`：キーは `^[a-z][a-zA-Z0-9]{0,31}$`、値は真偽値・数値・制御文字と `<>` を含まない 120 文字までの文字列。最大 16 件。**コード・URL・オブジェクトは受け付けない**。

### 5.2 将来の受け渡し形式（案）

サイトから Motion Studio を開く入口ができた場合の、受け渡しデータの案：

```json
{
  "format": "omochix.design-to-motion-studio",
  "version": 1,
  "workId": "dl-video-0001",
  "templateId": "rag-intro",
  "settings": { "title": "…", "accent": "#a78bfa" }
}
```

- 渡すのは**値だけ**。テンプレートのコード・HTML・スクリプトは渡さない（SVG Motion Studio の境界と同じ考え方）。
- Motion Studio 側は、`templateId` が自分の登録一覧にあるか、`settings` の各キーがそのテンプレートの受け付けるパラメーター（型・範囲・長さ）か、をもう一度検証する。
- URL に載せる場合も、値をコードとして評価しない。文字列は表示用のテキストとしてだけ使う。

### 5.3 制作ボタンを出す条件

`omochix_design_motion_studio_url()` は、D1.5 では**常に空文字**を返す（試験で固定）。次のすべてを満たすまで変えない。

1. Motion Studio の編集画面、またはテンプレートを読み込む API が実在し、サイトから到達できる（ローカル開発サーバーは対象外）。
2. 実際にその入口へ §5.2 の形式で値を渡し、編集・書き出しまでできることを確認した。
3. 受け渡しの安全性（任意コードが実行されない、他人の作品を上書きしない、認証・権限）を確認した。
4. 運用者の承認を得た。

それまでは、詳細ページの「制作手順」（このページ内）と、関連する Learn・Gallery のページへの導線だけを出す。
